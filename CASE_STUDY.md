# Case Study: Vitality AI - Clinical-Grade Health Assistant

## Overview
**Vitality AI** is an advanced, decoupled Health and Fitness ecosystem designed to provide clinical-grade, fact-checked, and highly personalized health insights. Unlike standard fitness chatbots, Vitality goes beyond generic advice by utilizing a sophisticated dual-agent architecture, live medical journal citations (RAG), and a permanent clinical memory store.

## The Challenge
The digital health market is saturated with generic AI chatbots that lack true medical safety guardrails, contextual memory, and verifiable sources. Users often receive hallucinated nutritional facts or unsafe medical advice. 
The goal was to engineer a solution that addressed these critical flaws by providing:
1. **Uncompromised Safety:** Real-time evaluation of AI outputs to prevent dangerous medical advice.
2. **Contextual Awareness:** Long-term memory of the user's specific health trajectory (e.g., past lab results, weight tracking).
3. **Verifiable Truth:** Answers backed by actual clinical studies and live nutritional databases, rather than LLM approximations.
4. **Data Privacy:** Strict Zero-Data-Retention compliance for external LLM calls.

## The Solution
I architected and developed a robust, decoupled three-tier microservice application that separates the user interface, data privacy layer, and AI intelligence.

### 1. Dual-Agent Medical Triage
To ensure user safety, I implemented a "Dual-Agent" system. Every response generated by the primary Large Language Model (LLM) is secretly intercepted by an "Evaluator LLM". This secondary agent specifically screens for extreme calorie deficits, harmful advice, or medical emergencies (e.g., reports of chest pain). If a risk is detected, the system immediately overrides the standard response with an `EMERGENCY_TRIAGE` protocol, triggering a distinct UI alert.

### 2. Persistent Clinical Memory
I built a system where the AI truly "remembers" the user. The Node.js backend actively queries the user's historical SQLite data—including weight logs, daily caloric intake, and past lab results (like LDL cholesterol). This clinical context is dynamically injected into the agent's prompt during every interaction, giving the AI a long-term understanding of the user's health journey.

### 3. Live Fact-Checking & RAG Implementation
To eliminate hallucinations, I integrated Retrieval-Augmented Generation (RAG). When a user asks about supplements, diets, or medical queries, the Python agent queries the PubMed API to retrieve peer-reviewed clinical studies. It also integrates with the USDA FoodData Central API for live, accurate nutritional facts. The responses are generated with explicit citations.

### 4. PII Scrubbing & Privacy
Before any user context is sent from the backend to the external Python AI engine, the Node.js proxy dynamically scrubs Personally Identifiable Information (PII) such as emails and phone numbers. This guarantees that no sensitive user data is exposed to external LLM providers.

### 5. Rich, Action-Driven UI
Instead of a generic text chat, the React frontend is designed to parse specific `actionType` flags returned by the AI agent. This allows the UI to render beautiful, native components dynamically:
- **Red Medical Sirens:** For emergency triages.
- **Green Nutritional Fact Sheets:** For logged meals and calorie tracking.
- **Blue PubMed Citations:** For verified medical research.

## Architecture & Tech Stack

The platform is decoupled into three distinct microservices, ensuring high scalability and a clean separation of concerns.

### Frontend (User Interface)
- **Framework:** React 19, Vite, TypeScript
- **Styling & UI:** Tailwind CSS v4, shadcn UI, Framer Motion (for smooth micro-animations), Lucide React
- **Data Visualization:** Recharts (for health metrics tracking)
- **Role:** Handles the rich, interactive AI Copilot interface, visualizes data, and communicates securely with the API proxy.

### Backend (API Proxy & Database)
- **Framework:** Node.js, Express, TypeScript
- **Database:** SQLite (managed via SQLite3)
- **Security:** bcryptjs, JSON Web Tokens (JWT) for authentication
- **Role:** Acts as the secure middle layer. It manages user sessions, stores clinical data/metrics, performs PII scrubbing, and routes sanitized requests to the AI engine.

### AI Engine ("The Brain")
- **Framework:** Python, FastAPI
- **AI / LLM:** Groq (Llama-3 models) for ultra-fast inference
- **Vector Store:** ChromaDB (for embeddings and RAG)
- **Integrations:** USDA API (Nutrition), PubMed API / NCBI E-utilities (Medical Studies)
- **Role:** Houses the Dual-Agent logic, performs real-time fact-checking, and generates intelligent, context-aware responses.

## Key Takeaways & Impact
Building Vitality AI demonstrated my ability to architect complex, AI-driven applications that prioritize user safety and data integrity. By moving away from monolithic architectures and embracing microservices, I ensured that the heavy AI processing (Python) didn't bottleneck the secure data routing (Node.js) or the snappy user experience (React). 

This project successfully bridges the gap between generic AI wrappers and true, clinical-grade health assistants, proving that with the right architecture (Dual-Agents, RAG, and strict data scrubbing), AI can be safely deployed in the sensitive health sector.
